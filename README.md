# SimLegacy 3.0 — Smart Dynasty Studio

Полноценный исходный проект для продолжения разработки на Vercel. Он **не публикуется автоматически из архива**. Обновление основано на SimLegacy 2.4 и сохраняет прежний интерфейс, Tinder-подобный мастер создания симов, ручное перемещение карточек, линии родства, масштабирование и фотоархивы.

## Что добавлено по аудиту функций

| Раздел | Где найти | Действие |
|---|---|---|
| Умная компоновка | В редакторе **Упорядочить** | Автоматически раскладывает поколения, пары и детей, не удаляя данные |
| Ручное/автоматическое расположение | **Настроить** | Режим `auto` перестраивает после изменения связей; ручное перетаскивание переключает обратно в `manual` |
| Наследники | Выберите сима → **Назначить наследником** | Золотой значок и выделенная родственная линия |
| Сворачивание веток | Выберите сима → **Свернуть ветку** | Временно скрывает потомков, не меняя сохранённые связи |
| Питомцы | **Питомец** в верхней панели | Кошки, собаки, лошади; фото, кличка, хозяин, статус, отдельные значки и линия хозяина |
| Навыки/карьера/стремления/черты | Карточка сима → **Симология** | Каталоги и редактируемые шкалы навыков 1–10, теги, тип персонажа |
| Дневник жизни | Карточка сима → **Дневник** | События, даты, фотографии, личные/публичные записи |
| Произвольные поля | Карточка сима → **Свои поля** | Добавление/редактирование/удаление полей, публичное или личное значение |
| Фотоальбомы с папками | Фото сима / Фото династии | Папки по темам, подписи, отметка «Личное фото» |
| Оформление | **Настроить** | 4 цвета линий, толщина, скругления, показ значков, кинематографичный фон |
| Фильтры | Над древом | По поколению, виду персонажа, статусу, тегу и поиску |
| Связанный сим в двух династиях | Выберите сима → **В другую династию** | Создаёт связанного персонажа в другом своём дереве; профиль синхронизируется при редактировании, положение и отношения — независимы |
| Книга поколений | Кнопка **Книга поколений** | Перелистывание поколений с портретами и событиями |
| Галерея сообщества | **Галерея** с Supabase | Публичные деревья, поиск, сортировки, лайки, комментарии, авторы |
| Профиль автора | **Аккаунт**, **Авторы** в галерее | Публичный ник, биография и опубликованные династии |

Также сохранены статусы жизни/смерти, причины смерти, семейные связи, защита от циклов родства, фото персонажа, фотоархив династии, экспорт и импорт JSON.

## Публикация на Vercel

1. **Сделайте резервную копию:** в текущем сайте откройте нужную династию → «Экспорт». В локальном режиме данные живут только в браузере.
2. Распакуйте архив и откройте папку `simlegacy-v2`. В GitHub `impislat/simlegacy-v2` замените содержимое проекта, сохранив папки `src/`, `supabase/`, `tests/`. Не загружайте ZIP как один файл в репозиторий.
3. На Vercel используйте **Framework: Vite**, **Build: `npm run build`**, **Output: `dist`**, **Install: `npm install`**. После коммита Vercel пересоберёт сайт, если GitHub подключён.
4. Без Supabase **личные династии, фото, навыки, отношения, дневники и настройки доступны локально**. В этом случае регистрация, лайки, общая галерея и облачная синхронизация недоступны.
5. Для сетевых возможностей создайте Supabase-проект и **перед обновлением сайта** выполните полный `supabase/schema.sql` в SQL Editor. Он обновляет существующую схему без удаления деревьев, создаёт таблицы лайков, комментариев и публичных версий дерева, обновляет RLS. Подключите переменные Vercel `VITE_SUPABASE_URL` (Project URL вида `https://…supabase.co`) и `VITE_SUPABASE_ANON_KEY` (ключ `sb_publishable_…` или `anon`). Никогда не добавляйте `sb_secret_…` или `service_role` в Vite!
6. Добавьте адрес Vercel в Supabase Authentication → URL Configuration → Site URL / Redirect URLs. Включите email provider.
7. После обновления SQL **откройте каждую ранее опубликованную династию и пересохраните либо выключите и включите публикацию**. Старые общие деревья не появятся в новой публичной галерее до создания очищенных снимков.

**Проверка после развёртывания:** создайте персонажей и питомца; перетащите карточку; нажмите «Упорядочить»; сохраните навык, дневник и личное фото; проверьте экспорт/импорт и сохранение после F5. При подключённом Supabase создайте два аккаунта и проверьте, что один аккаунт **не** видит личные династии другого, но видит опубликованные; попробуйте лайк и комментарий. Для тестирования приватности добавьте в личный дневник заметку, опубликуйте дерево и проверьте в другом аккаунте, что заметка отсутствует.

## Приватность

`trees` в Supabase доступна только владельцу. Публичный сайт читает **только `public_tree_snapshots`**, в которых нет личных заметок, закрытых фото и событий, скрытых дополнительных полей и ID связанных персонажей других династий. SQL удаляет старую публичную политику чтения приватного JSON и добавляет триггер снятия публикации.

**Ограничение фото:** bucket `sim-images` публичный. Отметка «Личное фото» скрывает снимок из опубликованного дерева и галереи, **но не от человека с прямой ссылкой на уже загруженный файл**. Для строго конфиденциальных фотографий потребуется отдельный приватный bucket, подписанные URL и миграция существующих файлов. Не загружайте туда чувствительные личные фотографии до такого изменения.

В локальном режиме фотографии сжимаются и хранятся в `localStorage`; это ограничено объёмом хранилища браузера. Делайте регулярный JSON-экспорт. При переходе с локального режима на Supabase автоматическая миграция **не** выполняется — импортируйте свои JSON-резервные копии после настройки сервера.

## Проверки исходного кода

- `node --test tests/*.test.js` — тесты отношений, мастера создания, статуса смерти, альбомов, умного дерева, наследования, закрытых данных и синхронизации симов.
- JSX/JS проверяются через локально доступный TypeScript JSX parser.
- `npm run build` **не выполнен в этой среде**: доступ к npmjs.org отсутствует (`EAI_AGAIN`). Окончательный production build и e2e-тест с Supabase должны пройти на Vercel.

Это независимый фанатский проект. EA, Maxis и The Sims 4 не являются его разработчиками или партнёрами. Гайд The Sims Tree использовался как ориентир для структуры функций, исходные изображения и код референса не копировались.

## SimLegacy 3.1 — Claymorphism

Новый визуальный стиль всех основных экранов: мягкие объёмные формы, пастельные мятные/лавандовые/персиковые акценты, тактильные кнопки с состоянием нажатия, внутренние тени у полей, выразительные фотокарточки и деликатная анимация. Логика и формат данных SimLegacy 3.0 сохранены.

**Как обновить с 3.0:** сделайте резервную копию династий через экспорт JSON; замените в репозитории файлы `src/main.jsx`, `src/TreeAppearance.jsx` и добавьте `src/clay.css` из этой версии. Если у вас есть другие несохранённые доработки, объедините изменения в Git, а не перезаписывайте их. Vercel пересоберёт проект после коммита. Изменение оформления не требует SQL-миграции или Supabase.

**Настройка темы:** весь Claymorphism находится в `src/clay.css`, который подключается последним, поверх существующих стилей. Палитра меняется в `:root`; разметка и модель данных не переписаны. На устройствах с `prefers-reduced-motion: reduce` анимации сокращаются.

**Проверка:** существующие 35 модульных тестов выполняются через `node --test tests/*.test.js`. Полная сборка `npm run build` зависит от установки npm-пакетов, которая в текущем окружении недоступна; после загрузки на Vercel проверьте результат сборки, интерфейс, вход в дерево и открытие редактора.

## SimLegacy 3.2 — Vivid Clay Studio (визуальное обновление)

Это обновление **не меняет структуру династий**, семейные отношения, таблицы Supabase или локальные ключи `simlegacy_v2_local` / `simlegacy_v2_active`. Продолжают работать все возможности SimLegacy 3.1.

**В интерфейсе добавлено:**

- Три переключаемые палитры: **Аврора** (фиолетово-розово-бирюзовая), **Закат** (кораллово-розовая), **Лагуна** (голубая и мятная). Выбор в виде трёх кружков наверху; палитра хранится в браузере под ключом `simlegacy_visual_theme`.
- Более яркие объёмные панели, навигация и кнопки в редакторе, фотоколлаж в демонстрационной части главной, иллюстрации и настоящие фотографии из Unsplash в декоративных блоках.
- Цветная подложка холста. При использовании собственного фона династии пользовательская обложка имеет приоритет над декоративным изображением.
- Компактная 2×2 легенда связей, новые оттенки карточек и подложки отсутствующих аватаров. Пользовательские фотографии не заменяются.
- Улучшенные цвета окон создания сима, фотоальбомов, дневников и кнопок.

### Быстрое обновление GitHub → Vercel

Если у вас уже развёрнут **SimLegacy 3.1**, достаточно:

1. Экспортировать династии в JSON, особенно без Supabase (на всякий случай).
2. Заменить файл `src/main.jsx` и `index.html`.
3. Добавить файлы `src/vivid.css`, `src/visualAssets.js`, `PHOTO_SOURCES.md`.
4. Выполнить commit в репозитории с подключенным Vercel и дождаться статуса `Ready`.

Если вы обновляете более старую версию, используйте **полный архив**, иначе могут отсутствовать компоненты SimLegacy 3.0–3.1.

**Изображения:** 5 специально подобранных декоративных изображений взяты с бесплатных страниц Unsplash. Используются внешние HTTPS-ссылки из `src/visualAssets.js` и `src/vivid.css`; для их загрузки у посетителя должен быть интернет. Если Unsplash недоступен, видны встроенные градиентные подложки. Источники и лицензии — `PHOTO_SOURCES.md`. Ни одна декоративная фотография не выдаётся за фотографию пользователя или работу в общественной галерее.

**Проверки:** `node --test tests/*.test.js` (35 тестов) и статическая проверка синтаксиса JSX/JS и CSS. Полная сборка Vite и осмотр живого сайта в браузере в этом окружении не подтверждены; проверяйте публикацию через Vercel Deployments. В версии 3.2 не требуется миграция SQL или подключение Supabase для смены оформления.
